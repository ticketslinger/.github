# Contributing to TicketSlinger

Thanks for wanting to help. Here's how a change gets in.

## Before you write code

Open an issue first for anything bigger than a typo, so we can agree on the approach before you spend an evening on it. Questions go in [Discussions](https://github.com/ticketslinger/ticketslinger/discussions), not issues.

## Making the change

1. Fork the repo and branch from `main`.
2. Keep the change focused. One fix or feature per pull request.
3. Add or update tests for anything that changes behaviour.
4. Write commit messages in [Conventional Commits](https://www.conventionalcommits.org/) form, for example `fix: reject orders after the quota is sold out`.
5. Open a pull request and fill in the template.

Nobody pushes to `main` directly, maintainers included. Every change lands through a pull request with green checks.

## The CLA

The first time you open a pull request, a bot asks you to sign our [Contributor License Agreement](CLA.md). It takes one click. It lets us offer TicketSlinger under AGPLv3 and under a commercial license, which is what pays for the project.

## Code of conduct

Everyone here follows our [Code of Conduct](CODE_OF_CONDUCT.md).
